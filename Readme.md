# blog

The blog/portfolio that powers `jamell.dev`, built on [Next.js](https://nextjs.org/)
(App Router) and self-hosted via Docker Compose + Caddy.

## How to run

```bash
pnpm install
pnpm dev
```

Requires a Redis instance for view counts — set `REDIS_URL` (defaults to
`redis://redis:6379`, matching the `docker-compose.yaml` service name).

### Production

```bash
docker compose build
docker compose up -d
```

## Architecture

### Posts

Posts are `.mdx` files in `posts/`, named `YYYY-MM-DD-slug.md(x)`, with
`title` / `date` / `tags` frontmatter. Drop a new file in and it's live —
`lib/posts.ts` scans the directory at request time, no code changes or
route registration needed. Rendered through
[`next-mdx-remote/rsc`](https://github.com/vercel/next-mdx-remote), so posts
can embed real JSX/React components (see `app/(post)/components/` for the
custom element mapping — headings, code blocks, callouts, tweets, etc.),
not just plain markdown.

Routes are `/[year]/[slug]`, generated via `generateStaticParams` in
`app/(post)/[year]/[slug]/page.tsx`.

### Components

Every stateless pure component is found under `./components`.

Every component that has to do with styling a post's markup is found under
`app/(post)/components/` — this is the *style guide* of the application, and
is reused as the MDX component mapping.

### Ambient background + ASCII art

`app/ambient-background.tsx` runs a full-viewport particle simulation
(adapted from `friend-enemy-dots.tsx`, itself an implementation of Simon
Woods' "Dancing with friends and enemies") behind all page content. The
homepage hero (`app/lain-portrait.tsx`) renders a Serial Experiments
Lain-inspired ASCII portrait generated by `scripts/ascii-art.py` — see that
script for the block-character density-mapping approach.

### Infra

- **Views**: self-hosted Redis (`app/redis.ts`, via `ioredis`), replacing the
  original `@upstash/redis` REST client.
- **Analytics**: self-hosted [Umami](https://umami.is) (`app/analytics.tsx`),
  replacing `@vercel/analytics`.
- **Deploy**: push-to-deploy via a repo-scoped self-hosted GitHub Actions
  runner (see `.github/workflows/deploy.yml`).
